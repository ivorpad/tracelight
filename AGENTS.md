# Agents

To establish what a JavaScript or TypeScript file did, use Tracelight runtime evidence: `skills/tracelight/SKILL.md` is the one skill, with a mode as its first argument. `ask` answers a question about code in chat from a recording of it running, including hidden failures, what an edit changed and profiles (`references/ask.md`), `debug` pauses a running program and tests hypotheses (`references/debug.md`), `explain` supports interactive learning in the editor or browser page, with optional guided teaching (`references/explain.md`), `show` investigates and hands over a tour or a code-history page whose every value `tracelight history` generated from the run (`references/show.md`). For interactive learning, inspect relevant source and callers first, plan in memory, propose useful breakpoints, then start paused at the first stop. Support jumps directed by voice or chat and explanations from manual-step pause events. For debugging, choose stops that test a hypothesis. No preliminary recording is required. Source inspection establishes where to look, not what a run observed.
The command reference is `skills/tracelight/references/tracelight-cli.md` (every verb and flag; `node/test/skill.test.ts` keeps it complete), the page's contract `references/code-history.md`, the debugger's `references/live-debugger.md`, the browser page's `references/browser.md`, the Claude Code band's `references/band.md`.
For a recording, start with `tracelight story run.json --file FILE` (the map, one step number per line) and `tracelight step run.json N --into` (land in the callee with its arguments). For live execution, `tracelight debug FILE --at NAME` starts it and prints the first stop; repeat `--at` for several stages and use `continue --live` between them.
Run the CLI as `tracelight ...` (the extension keeps `~/.local/bin/tracelight` pointing at its runtime while `tracelight.agentAccess` is on), or from this checkout as `node node/bin/tracelight.mjs ...` after `npm ci --prefix node`; `--live` instead of `run.json` drives the open VS Code session.
MCP clients get the same commands as tools from `tracelight mcp` (`skills/tracelight/references/mcp.md`).
For live browser learning, start `tracelight web FILE --no-run --no-watch`, open the page, set breakpoints, then use `tracelight web ctl debug start` and `debug continue`. Use recording `step` only when reviewing a recording. From a checkout after `npm run build`, `node dist/web/server.js` takes the same arguments (`docs/WEB.md`, `references/browser.md`).
Build, test and quirks for working on the extension itself: `docs/HANDOFF.md`; the runtime's layout: `docs/RUNTIME.md`; wire contract: `docs/PROTOCOL.md`.
